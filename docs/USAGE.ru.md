# Stellara MCP — инструкция для пользователя

`stellara-mcp` — это небольшой сервер [Model Context Protocol](https://modelcontextprotocol.io),
который даёт вашему ИИ-агенту (Claude, ChatGPT, Codex, Cursor, Windsurf, Gemini CLI, Grok и любому
другому MCP-совместимому) **точные астрономические расчёты**: натальную карту, транзиты и
синастрию на движке Swiss Ephemeris. Сам сервер ничего не интерпретирует и не вызывает языковые
модели — он возвращает числа в JSON, а толкует их ваш агент. Поэтому в карте не бывает
«выдуманных» куспидов домов или орбисов.

Подключиться можно двумя способами:

| | По ссылке, без установки (раздел 0) | Локальный пакет + API-ключ (разделы 1–2) |
| --- | --- | --- |
| Кому подходит | Claude.ai / Claude Desktop / Claude Code, ChatGPT-коннекторы, Grok, любой клиент с полем «MCP server URL» | Серверы, скрипты, IDE-агенты (Cursor, Windsurf, Codex CLI, Gemini CLI), Hermes |
| Что нужно | аккаунт Stellara (тот же, что в приложении) | Node.js 18+ и ключ `sk_stellara_…` с https://stellara.natlex.it/#api |
| Лимит | Free — 10 запросов в день, **Stellara Pro** (подписка в приложении) — 5 000 | Free-ключ — 5 запросов в день, **Stellara API Pro** ($9/мес) — 5 000 |
| Где считается квота | на аккаунт, сброс в 00:00 UTC | на ключ, сброс в 00:00 UTC |

## 0. Без установки: подключение по ссылке

Адрес сервера: **`https://mcp.stellara.natlex.it/mcp`**. Вход — аккаунтом Stellara (e-mail и
пароль из приложения; если входили через Google или Apple — сначала задайте пароль через
«Забыли пароль?» в приложении).

- **Claude.ai / Claude Desktop**: Settings → Connectors → **Add custom connector** → Name
  `Stellara`, MCP server URL `https://mcp.stellara.natlex.it/mcp` → Continue → в браузере
  откроется страница «Разрешить доступ к вашему аккаунту Stellara?» → e-mail, пароль →
  **«Войти и разрешить»** → коннектор станет Connected. В чате проверьте, что инструменты
  Stellara включены в меню инструментов.
- **Claude Code**: `claude mcp add --transport http stellara https://mcp.stellara.natlex.it/mcp`,
  затем в сессии `/mcp` → Authenticate → вход в браузере.
- **ChatGPT** (коннекторы в режиме разработчика), **Grok**, **Codex** (тип «Потоковая передача
  HTTP»), **Cursor / Windsurf** (transport `streamable-http` / `url`): вставьте тот же URL и
  войдите, когда клиент откроет страницу входа.
- **Отключить**: удалите коннектор в клиенте — сессия отзывается; все входы разом отзываются
  сменой пароля в приложении.

Доступ короткоживущий (токен на 30 минут, продлевается автоматически), ключей нет, данные
рождения на сервере не хранятся. Если клиент пишет «Couldn't reach the MCP server» — проверьте,
что URL введён точно как выше (с `/mcp`, без завершающего слэша).

## 2. Подключение (один раз, 2 минуты)

Во всех клиентах конфигурация одинаковая — три строки: команда, аргументы, переменные окружения.
Устанавливать пакет отдельно не нужно: `npx -y stellara-mcp` скачает его при первом запуске.

### Claude Desktop

Файл `claude_desktop_config.json`:
- Windows: `%APPDATA%\Claude\claude_desktop_config.json`
- macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`

(В приложении: Settings → Developer → Edit Config.)

```json
{
  "mcpServers": {
    "stellara": {
      "command": "npx",
      "args": ["-y", "stellara-mcp"],
      "env": {
        "STELLARA_API_KEY": "sk_stellara_ваш_ключ"
      }
    }
  }
}
```

Полностью перезапустите Claude Desktop. Инструменты появятся под значком 🔌 (или «Search and tools»),
промпты — в меню «+».

### Cursor

Settings → MCP → **Add new global MCP server** (или файл `.cursor/mcp.json` в проекте) — тот же JSON.

### Windsurf

Settings → Cascade → MCP servers (или `~/.codeium/windsurf/mcp_config.json`) — тот же JSON.

### Hermes Agent Desktop

Тот же блок `mcpServers` в `~/.hermes/config.json`.

### OpenAI Codex (CLI и приложение)

CLI — файл `~/.codex/config.toml`:

```toml
[mcp_servers.stellara]
command = "npx"
args = ["-y", "stellara-mcp"]
env = { STELLARA_API_KEY = "sk_stellara_ваш_ключ" }
```

Приложение Codex — «Подключиться к пользовательскому MCP»: имя `stellara`, тип **STDIO**,
команда `npx` (Windows: `npx.cmd`), аргументы двумя строками `-y` и `stellara-mcp`, переменная
окружения `STELLARA_API_KEY` = ключ. Или тип «Потоковая передача HTTP» с URL из раздела 0.

### Gemini CLI

`~/.gemini/settings.json` → тот же блок `mcpServers`; либо расширение:
`gemini extensions install https://github.com/mihnin/stellara-gemini-extension` (спросит ключ).

### VS Code (Copilot)

`.vscode/mcp.json` — обратите внимание на ключ `servers`, а не `mcpServers`:

```json
{ "servers": { "stellara": { "type": "stdio",
    "command": "npx", "args": ["-y", "stellara-mcp"],
    "env": { "STELLARA_API_KEY": "sk_stellara_ваш_ключ" } } } }
```

### ChatGPT без remote-MCP (Custom GPT)

Если нужен именно Custom GPT: Actions по схеме https://stellara.natlex.it/openapi-gpt.json,
аутентификация API key, заголовок `X-API-Key` — пошагово в `docs/GPT_ACTION.ru.md`.

### Любой другой клиент

Запускайте `npx -y stellara-mcp` как **stdio**-сервер с переменной окружения `STELLARA_API_KEY`.

> Windows: если `npx` не находится, укажите полный путь `C:\Program Files\nodejs\npx.cmd`.

## 3. Первый диалог

Самый надёжный сценарий — сначала попросить агента собрать данные рождения, затем строить карту.

1. Выберите промпт **`collect_birth_profile`** (в Claude Desktop — меню «+» → Prompts) или просто
   напишите: *«Собери мой профиль для астрологического расчёта»*.
2. Агент спросит по порядку: дату рождения → время (и насколько оно точное) → место рождения →
   город, где вы живёте сейчас (только чтобы правильно понимать «сегодня») → имя (по желанию).
   Пол спрашивается только для расчёта совместимости.
3. Агент вызовет `resolve_birth_place` — вы увидите найденный город, координаты и часовой пояс.
   Проверьте, что это тот самый город.
4. Подтвердите сводку — и просите что угодно:
   - *«Построй мою натальную карту и опиши главные аспекты»*
   - *«Почему мне сегодня тяжело сосредоточиться?»* — агент возьмёт транзиты на сегодня
   - *«Проверь совместимость с партнёром: 3 ноября 1992, 06:15, Алматы»*

Для профессионального стиля толкования подключите промпт **`astrologer_system_prompt`**
(аргументы: `language` — язык ответа, `focus` — ваш вопрос).

Пример запроса без промпта — тоже работает:

> Я родился 17 мая 1990 в 14:30 в Варшаве. Построй натальную карту и скажи, что сейчас
> происходит по транзитам.

## 4. Что умеет каждый инструмент

| Инструмент | Что делает | Что возвращает |
| --- | --- | --- |
| `resolve_birth_place` | Место (любой язык) + **местное** время рождения без смещения → координаты, часовой пояс IANA, исторически верное смещение UTC | `latitude`, `longitude`, `timezone`, `utc_offset`, готовый `birth_datetime`, `age_years`, флаги `time_assumed_noon` (время не указано → взято 12:00) и `local_time_ambiguity` (перевод часов — время было дважды или его не было) |
| `calculate_natal_chart` | Натальная карта | 14 точек (Солнце…Плутон, Хирон, Лилит, узлы) — знак, градус, дом, ретроградность, скорость, склонение; 12 куспидов; ASC / MC / DSC / IC; мажорные аспекты с точным орбисом и applying/separating. Опции: `house_system` (10 систем, по умолчанию Placidus), `include_minor_aspects` |
| `get_transits_and_aspects` | Транзиты на любой момент | положения транзитных планет, в каком натальном доме каждая, все аспекты транзит → натал с орбисом и applying/separating |
| `calculate_synastry` | Совместимость двух людей | все межкарточные аспекты с орбисами + наложения домов (планеты A в домах B и наоборот) |

Правила данных, которые агент соблюдает сам (но полезно знать):
- время рождения — **местное**, как в свидетельстве; смещение UTC добавляет сервер;
- если время неизвестно — берётся 12:00, и агент не должен толковать асцендент и дома;
- координаты и часовые пояса агент не «вспоминает», а берёт из `resolve_birth_place`.

## 5. Если что-то пошло не так

| Сообщение | Причина | Что делать |
| --- | --- | --- |
| `STELLARA_API_KEY is not set…` | Ключ не попал в конфиг | Проверьте блок `env` в JSON и перезапустите клиент |
| `…rejected the access key (HTTP 401)…` | Ключ неверный или отозван | Сверьте ключ посимвольно; запросите новый на https://stellara.natlex.it/#api |
| `The daily quota for this Stellara API key is used up (HTTP 429, QUOTA_EXCEEDED)…` | Дневной лимит ключа исчерпан (Free — 5 запросов) | Подождать до 00:00 UTC или перейти на API Pro (5 000/день) на https://stellara.natlex.it/#api |
| `Place not found by the geocoder…` | Геокодер не понял название | Добавьте регион и страну («Springfield, Illinois, USA») или укажите ближайший крупный город |
| `…geocoding service … temporarily unavailable…` | Внешний геокодер не ответил | Повторите через минуту; место, скорее всего, существует |
| `…rate limit reached…` | Больше 60 запросов в минуту (20 для геокодера) | Подождите минуту |
| `…timed out after 15000 ms…` | Сеть / медленный ответ | Повторите; при постоянных таймаутах задайте `STELLARA_TIMEOUT_MS=30000` в `env` |
| Инструменты не появились | Клиент не перезапущен / ошибка в JSON | Проверьте JSON на валидность, перезапустите клиент; в Claude Desktop смотрите Settings → Developer → логи |
| Инструменты подключены, но агент считает карту «из головы» или ищет в интернете | Хост (Grok, ChatGPT, Gemini) сам решает, звать ли коннектор; в старых чатах он мог запомнить, что Stellara «не нужна» | Начните **новый чат** (описание сервера с правилом «всегда вызывай инструменты при гороскопе / натальной карте / дате рождения» подхватывается при подключении). Если не помогло — добавьте в постоянные инструкции агента (Grok → Settings → Customize; ChatGPT → Custom instructions; Gemini → Saved info) одну строку: *«Для любого гороскопа, натальной карты, транзитов и совместимости всегда используй инструменты Stellara (сначала resolve_birth_place, потом calculate_natal_chart / get_transits_and_aspects / calculate_synastry); никогда не считай положения планет сам и не ищи их в интернете»*. В разовом запросе достаточно приписать «через Stellara» |

## 5a. Тарифы и оплата

| | Free | Pro |
| --- | --- | --- |
| По ссылке (аккаунт Stellara) | 10 запросов в день | **Stellara Pro** — подписка в приложении (Google Play / App Store), 5 000 в день |
| По API-ключу | 5 запросов в день, один активный ключ на e-mail | **Stellara API Pro** — $9 в месяц, 5 000 в день, оплата картой через Stripe на https://stellara.natlex.it/#api |

Один запрос = один вызов инструмента. Полный разбор одного человека — 2 запроса (место + карта),
транзиты на дату — ещё 1, синастрия — 2. Квоты сбрасываются в 00:00 UTC; при превышении агент
получает понятное сообщение с временем сброса.

**Как отменить API Pro**: на https://stellara.natlex.it/#api → «Управление подпиской Pro» →
вставьте ключ → «Открыть портал клиента» (Stripe): отмена, смена карты, счета. Доступ
сохраняется до конца оплаченного периода; при возврате платежа ключ отзывается сразу.
Подписка приложения (Stellara Pro) отменяется в Google Play / App Store, как обычно.

## 6. Приватность

Сервер работает на вашем компьютере. В облако уходят только числа, нужные для расчёта
(дата-время, координаты, название места) — **ничего не сохраняется** на стороне Stellara,
профиль не создаётся. Имя и пол на сервер не передаются вовсе.

## 7. Обновление

`npx -y stellara-mcp` каждый раз использует кэш npm. Чтобы получить новую версию:

```bash
npx -y stellara-mcp@latest
```

или очистите кэш: `npx clear-npx-cache`, затем перезапустите клиент.
